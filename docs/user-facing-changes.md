# PeriTray 优化批次 — 用户可感知影响清单

> 分支：feat/optimization-batch1（8 批 · 37 项）
> 生成日期：2026-09-08
> 本文档面向普通用户写作：只写用户可感知的结果，不写实现机制。

---

## 一、用户可感知的 Bug 修复

### 蓝牙设备操作精准度提升

**影响场景**：用户同时拥有多只蓝牙设备（尤其同名蓝牙 + BLE 双模设备）时。

| 修复前 | 修复后 |
|--------|--------|
| 连接/断开可能操作错设备（两只同名设备互踩 device_id） | 精确操作目标设备，不再误操作 |
| 断开 A 设备可能报错"no BLE connection cached" | 每台 BLE 设备独立连接/断开，互不影响 |
| 连接失败（GATT 3 次超时）后再次点击同一设备显示"already connected"，必须手动断开才能重连 | 连接失败后可直接重试，无需手动清理 |

### 默认设备切换实时同步

**修复前**：切换 Windows 默认音频设备后，弹窗中的"默认"标记不实时更新，需等待设备增删事件才刷新。

**修复后**：切换默认设备后弹窗立即显示正确的"默认"标记。

### 更新检查版本比较修正

**修复前**：预发布版本号按字符串字典序比较，`beta.10` 会被判定为低于 `beta.2`（因为 "1" < "2"），导致漏提示升级。

**修复后**：预发布版本号按数字段数值比较，`beta.10` 正确判定为高于 `beta.2`。

### Toast 通知不再导致崩溃

**修复前**：通知器创建失败或系统锁中毒时进程直接崩溃退出。

**修复后**：通知器创建失败时静默降级（功能失效但进程稳定运行），日志记录失败原因。

### 配置文件写入不再丢数据

**修复前**：写入配置时先截断旧文件再写入，中途崩溃/断电会导致文件损坏，重启后全部配置丢失。

**修复后**：先写临时文件再原子替换，中途崩溃最多丢失未保存的改动，不会损坏已有配置。

### 关机音量 NaN 污染修复

**修复前**：关机音量 NumberBox 输入框清空后点 ▲/▼ 按钮产生 NaN，NaN 写入配置后导致后续**所有设置保存静默失效**，且该设备关机时被静音。

**修复后**：清空输入框后点按钮自动归零，不再产生 NaN，设置保存功能正常。

### 同名 BLE 设备不再合并为一张卡

**修复前**：两只同名 BLE 设备（如不同厂商）在弹窗中合并为一张卡，无法分别操作。

**修复后**：每只 BLE 设备独立显示，可分别连接/断开。

### 弹窗关闭时释放渲染资源

**修复前**：通过 Alt+F4 或关闭按钮关闭弹窗时仅隐藏窗口，WebView2 渲染进程持续运行、JS 定时器继续跑、内存不释放。

**修复后**：关闭弹窗时挂起 WebView2 渲染进程，释放 CPU 和内存资源。

### 强制静音状态清理

**修复前**：设备从"强制静音"列表移除后，内部记录的"静音前音量"永久残留（内存泄漏）。

**修复后**：非强制静音设备静音时自动清理残留记录。

## 二、性能与流畅度提升

### 音频会话操作卡顿改善

**影响场景**：拖动音量页的会话音量滑块时。

| 修复前 | 修复后 |
|--------|--------|
| 每次拖动（100ms 间隔）全量扫描所有设备所有会话（每秒 10 次 COM 枚举） | 仅扫描当前设备的会话，减少 90%+ 的 COM 调用 |

### 设备插拔抖动不再积压

**修复前**：设备插拔抖动时多条同义消息排队，每条触发全量重扫，STA 线程积压导致音量推送延迟。

**修复后**：多条同义消息合并为一条处理，STA 线程无积压。

### 窗口背景透明化更快

**修复前**：窗口背景透明设置无条件重试 4 次（累计 sleep ~3 秒）。

**修复后**：首次成功即停止（通常 300ms 内完成），窗口显示更快。

### 设置页设备列表刷新不再闪烁

**修复前**：每次 config-changed 事件（如切换主题/材质/快捷键等非设备变化）都完全重建 DOM，导致展开的分组折叠、滚动位置丢失、页面闪烁。

**修复后**：设备列表或分组映射无变化时跳过 DOM 重建，页面保持稳定。

### 配置保存更高效

**修复前**：每次配置变更都全量序列化 + 写盘（即使内容未变）。

**修复后**：序列化后与上次内容比对，未变化跳过写盘。

### 音频空间音效查询更快

**修复前**：每次检查 Dolby/DTS 空间音效支持都新建 PackageManager + WinRT 查询。

**修复后**：查询结果缓存 60 秒，重复查询直接返回缓存。

### VID/PID 查询合并

**修复前**：每个 USB 设备行最多 5 次重复解析 VID/PID。

**修复后**：行首解析一次，合并为单次查询。

### 日志写入更高效

**修复前**：每条日志都重新打开文件。

**修复后**：缓存文件句柄，跨天或配置切换时自动重建。

### BLE 多设备并行连接

**修复前**：BLE 连接为单槽，连接新设备后旧设备的系统级连接未释放。

**修复后**：支持多台 BLE 设备同时连接，每台设备独立管理。

### 焦点刷新复用

**修复前**：弹窗获焦时手工重写 15 行 config 赋值 + 渲染逻辑，与在途刷新可交叉写状态。

**修复后**：复用 `loadDevices()`，代码更简洁，无状态竞争。

## 三、安全与稳定性提升

### XSS 防护

**修复前**：Toast 通知内容通过 `innerHTML` 插入，错误信息中的特殊字符可被解释为 HTML。

**修复后**：使用 `textContent` 插入，杜绝 HTML 注入风险。

### 快捷键录制器内存泄漏修复

**修复前**：快捷键录制器（shortcutRecorders）只添加不移除，旧录制器闭包永久持有已卸载 DOM，Set 无界增长。

**修复后**：录制器提供 dispose 函数，DOM 卸载前调用清理，Set 不再增长。

### Config-changed 事件完整载荷

**修复前**：config-changed 事件不携带配置内容，前端每次收到事件后重新拉取配置（3+ 次 get_config）。

**修复后**：事件携带完整 Config 快照，前端直接使用，减少 IPC 调用。

### 音频设备枚举容错

**修复前**：单台设备 ID 转换失败导致整个设备列表返回错误，所有音频设备消失。

**修复后**：跳过异常设备，其余正常显示。

### 音频会话过滤

**修复前**：枚举音频会话时不区分设备，所有设备的会话混在一起。

**修复后**：按 device_id 裁剪，仅返回目标设备的会话。

### CoTaskMemFree 内存释放

**修复前**：设备 ID 字符串转换失败时不释放 COM 内存。

**修复后**：无论成功失败都无条件释放 COM 内存。

### 后台补查线程 panic 保护

**修复前**：后台电量补查线程 panic 后，单飞标志永久锁死，该通道电量刷新永远停止。

**修复后**：RAII 守卫在 Drop 时自动复位标志，panic 后仍可正常刷新。
