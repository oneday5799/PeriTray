# 02 · 架构总览

## 1. 三层架构

```
┌─────────────────────────────────────────────────────────────────┐
│ 前端（src-tauri/dist，WebView2 渲染，无构建）                      │
│   popup.html + scripts/common.js + popup-{audio,devices,}.js     │
│   settings.html + settings.js + settings-{general,shortcut,      │
│                  devices,audio,about}.js                          │
│   styles/base.css（设计令牌+共享基类）+ popup.css / settings.css   │
└──────────────┬──────────────────────────────▲───────────────────┘
               │ invoke(cmd, args)            │ emit(event, payload)
               ▼                              │ （后端 → 前端广播）
┌─────────────────────────────────────────────────────────────────┐
│ Tauri 桥接层                                                      │
│   invoke_handler 注册 ~40 个命令（main.rs:189-237）               │
│   事件总线：Emitter::emit / listen                                │
└──────────────┬──────────────────────────────▲───────────────────┘
               ▼                              │
┌─────────────────────────────────────────────────────────────────┐
│ Rust 后端（src-tauri/src，20 模块 ~6700 行）                       │
│   窗口域：main/popup/windows/tray/state                           │
│   设备域：wmi_query/bluetooth/classify/dedup/device_data/device   │
│   音频域：audio/audio_notify/audio_spatial                        │
│   支撑域：config/process/commands/shortcut/update/app_icon        │
│   底层互操作：windows crate / windows-sys crate / 手写 COM vtable │
└─────────────────────────────────────────────────────────────────┘
```

关键点：

- 前端**无框架、无打包器**，`cargo build` 时经 Tauri 的 `frontendDist` 配置嵌入二进制；改 dist 即热生效
- 后端对前端的推送全部走事件（`app.emit` 全局广播或 `emit_to("settings", ...)` 定向）；前端对后端全部走 `invoke`
- 双页各有独立生命周期：popup 可销毁重建（关闭即 hide + WebView Suspend），settings 关闭为"hide 先行 + 3s 延迟销毁"

## 2. 启动流程时序

`main()`（src-tauri/src/main.rs:110）按以下顺序执行：

1. **看门狗重启路径优先**（main.rs:114-122）：若带 `--watchdog-restart=<pid>` 参数，先 `OpenProcess + WaitForSingleObject` 内核级等旧实例死亡（最多 3s）——必须发生在一切初始化之前，否则 single-instance 插件的同步转发会撞上僵死窗口（复盘见 [06 §4.2](06-踩坑复盘-假死.md)）
2. `config::init_config()`：加载 JSON 配置到全局单例（panic hook 与日志都依赖它）
3. `install_panic_hook()`：panic 时落盘 `[panic]` 日志 + MessageBox 弹窗再退出（防 release 静默闪退）
4. `CoInitializeEx(COINIT_APARTMENTTHREADED)`：与 Tauri 同模式的 STA，使后续 wmi 可用 `COMLibrary::assume_initialized()`
5. `device_data::init_device_data()`（内置 2.4G 库）与 `tray::init_auto_start()`（读注册表同步 AUTO_START）
6. 日志保留策略清理旧日志；判断 `--autostart`
7. **Builder 组装**：
   - `autostart` 插件恒注册
   - `single_instance` 插件**仅非看门狗重启路径注册**（main.rs:166-185）；回调内重操作 spawn 移出
   - `window_state` / `global_shortcut` 插件
   - `invoke_handler` 注册全部命令
8. **setup 回调**（main.rs:238-348）：
   - 托盘建立（菜单构建 + 事件接线 + 后台线程启动）
   - `audio_notify::init_audio_notify`（专职 STA 线程 + 隐藏消息窗口）
   - `shortcut::register_shortcuts`
   - 非 autostart 则首启弹窗 `popup::open_popup(handle, "devices")`
   - `PM_DEV_OPEN_SETTINGS=1` 时延迟 1.5s 自动开设置窗（开发调试）
   - 非 autostart 且配置开启时延迟 3s 启动更新检查
   - **看门狗线程**（详见 [06 §5](06-踩坑复盘-假死.md)）：15s 心跳 + 时间跳变检测（唤醒后 Resume WebView2）+ is_visible 探活（连续 2 次 5s 超时判定僵死并自重启）
9. **on_window_event**（main.rs:349-385）：
   - `Focused(false)` on popup → spawn 调 `popup::close_popup`（失焦自动收起）
   - `CloseRequested` on settings → 阻止默认关闭、立即 hide、子线程 3s 后复查未重开才 destroy（A 类假死防线）
   - `CloseRequested` on popup → 阻止关闭、hide
10. `app.run(...)` 进入事件循环；启动完成打点 `[main] startup complete`（排查启动问题先找这行）

## 3. 核心数据流

### 3.1 设备查询管线（wmi_query.rs:51 `query_devices`）

```
reload_device_data()            # 重载 2.4G 内置库+用户库（带 mtime 缓存）
   ↓
WMIConnection（STA 复用主线程 COM）
   ├─ query_pnp_devices         # Win32_PnPEntity，PNPCLASS 白名单 → 结构过滤(PNPDeviceID)
   ├─ query_bt_devices          # WinRT 枚举已连蓝牙 + windows_pnp 读 BTC 电量
   └─ query_battery_devices     # Win32_Battery
   ↓
classify_device                 # VID/PID 匹配 2.4G 库路由类型（classify.rs）
   ↓
dedup::try_insert               # core_name(剥协议后缀)+连接类型 去重（cn_index 索引）
   ↓
正则过滤（配置开关，regex 编译缓存）
   ↓
WinRT 未覆盖的蓝牙设备清空 status（避免误显示连接态）
   ↓
Vec<Device> → state::DEVICES_CACHE（托盘轮询比对变化）/ get_devices 命令直接调用
```

### 3.2 音频事件推送链（事件驱动，无轮询）

```
audio_notify::init_audio_notify
  → 专职 STA 线程：COM 初始化 → 注册隐藏消息窗口 AudioNotifyMsgWindow
  → AudioMonitor::new(hwnd)：枚举设备/会话并注册回调
      · IAudioEndpointVolumeCallback   —— 设备音量/静音变化
      · IAudioSessionEvents::OnSimpleVolumeChanged —— 应用会话音量变化
  → SetTimer 每 3s sync_callbacks 对账：新会话补注册、失效会话摘除
  → 变化发生 → app.emit("volume-changed", {device_id|session_id, volume, is_muted})
  → popup-audio.js 监听实时刷新滑块
```

### 3.3 弹窗生命周期（popup.rs）

```
托盘左键 Click（事件线程）→ 仅记录 TRAY_POS + spawn toggle()
toggle(): ANIMATING 门禁 → compute_position（托盘坐标-宽高-15px；start_y=屏外）
  ├─ 已存在且可见 → close(): place_below_taskbar → 子线程 animate_close(200ms/16帧) → hide → suspend_webview
  ├─ 已存在不可见 → resume_webview → show(): 屏外定位→置顶→show→place_below_taskbar → 子线程 animate_open(250ms/20帧) → set_focus → 再沉降
  └─ 不存在 → create(): WebviewWindowBuilder（恒透明出生）→ 圆角/材质/webview透明 → show → 沉降
失焦（Focused=false）→ spawn close_popup（ANIMATING/is_visible 双防护，重复分发安全）
```

动画曲线为 `cubic-bezier(0.62, 0, 0.32, 1)`，用牛顿迭代求解贝塞尔方程反解 t 参数（popup.rs:12-28）。

### 3.4 配置变更传播

```
前端 update_config / 各 set_* 命令 → config::with_config_mut 写入内存单例 + 落盘 JSON
  → app.emit("config-changed") 广播
      ├─ tray.rs: 同步 AUTO_START 文本、托盘图标、音频子菜单
      ├─ common.js: 两页重应用主题/材质 CSS
      └─ settings.js / popup-audio.js: 相关面板刷新
```

## 4. 线程模型全景

| 线程 | 创建处 | 职责 | 备注 |
|------|--------|------|------|
| 主事件循环 | tauri run | 窗口消息、菜单分发、窗口事件回调 | **单点，禁止阻塞**（铁律见 [06](06-踩坑复盘-假死.md)） |
| 看门狗 | main.rs setup | 心跳/探活/自愈/唤醒恢复 | 15s 周期，最坏 ~40s 自愈 |
| 音频 STA | audio_notify.rs:356 | COM 回调接收 + 消息泵 | 隐藏窗口承载定时器 |
| 设备轮询 | tray.rs start_device_watcher | 10s 查询设备缓存，变化才更新 tooltip | 仅配置了托盘设备时工作 |
| 主题监听 | tray.rs start_theme_watcher | RegNotifyChangeKeyValue 事件驱动深浅色 | 无轮询 |
| tokio runtime | tauri async_runtime | 异步命令、更新检查、设置页创建 | |
| 临时 worker | 各处 std::thread::spawn | 动画/DWM/材质/WMI 查询等一切可能慢的操作 | 事件回调只做分发的产物 |

## 5. 全局状态与并发约定

state.rs + config.rs 集中管理全局状态：

```rust
TRAY_POS / POPUP_POS : OnceLock<Mutex<(f64, f64)>>   // 托盘与弹窗位置
ANIMATING            : AtomicBool                     // 弹窗动画门禁
AUTO_START           : AtomicBool                     // 自启状态镜像
AUTO_MENU_ITEM       : MenuItem（托盘勾选项句柄）
DEVICES_CACHE        : OnceLock<Mutex<Vec<Device>>>   // 设备轮询缓存
CONFIG               : OnceLock<Mutex<Config>>        // 配置单例
```

并发约定：

1. **Mutex 一律毒化容忍**——统一走 `state::lock_unpoisoned(guard)`（state.rs），禁止裸 `.unwrap()`（某次 panic 后的毒化不应演变为全局崩溃；此句式由 commit 2f423e4 收敛）
2. **跨线程 UI 操作必经 clone AppHandle 进子线程**，不持锁跨 await/spawn
3. **ANIMATING 是弹窗所有显隐操作的唯一门禁**——toggle/open_popup/close_popup 入口检查，动画起止置位；失焦重复分发靠它与 is_visible 双防护兜底幂等
