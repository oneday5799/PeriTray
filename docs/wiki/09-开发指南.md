# 09 · 开发指南

## 1. 本地运行与调试

```bash
npm install          # 仅 @tauri-apps/cli
npm run tauri dev    # 首次需编译 Rust
```

- 改 Rust 源 → dev 监听自动重建重启；改 `src-tauri/dist` 前端 → 热生效（无构建）
- 打 release 包：`npm run build`（NSIS）

### 调试开关与环境变量
| 手段 | 用法 | 场景 |
|------|------|------|
| `PM_DEV_OPEN_SETTINGS=1` | 启动时延迟 1.5s 自动打开设置窗口（main.rs:251） | 自动化验证设置页脚本加载与初始化 |
| `--autostart` 参数 | 静默启动不弹窗 | 模拟开机自启路径 |
| `--watchdog-restart=<pid>` | 内部协议，勿手工使用 | 看门狗自愈 |

### 日志系统
- 位置：`src-tauri/target/debug/debug.log`（exe 同目录）
- 开关与级别在 设置页「通用 → 日志」；保留策略可配
- 排查启动问题先找 `[main] startup complete`——没有它说明 setup 阶段就挂了
- 假死排查直接按 [06 §3](06-踩坑复盘-假死.md) 方法论走（心跳/事件打桩/看门狗 streak）
- panic 有 `[panic]` 前缀日志 + MessageBox 双通道

## 2. 常见任务 How-to

### 新增一个设置项
1. `config.rs`：Config 结构加字段（serde 默认值注意向后兼容——旧配置文件缺字段时反序列化策略）
2. `settings.html` + 对应 `settings-*.js`：UI 与绑定（bindToggle/createToggle/initComboBox 三选一）
3. 若需后端响应：commands.rs 或域模块消费新字段；广播 `config-changed` 让 tray/前端联动
4. settings.js 的 saveConfig 是唯一写入口，勿绕过

### 新增一个 Tauri 命令
1. 域模块实现业务函数（带日志前缀）
2. commands.rs 加 #[tauri::command] 薄封装（参数校验→调用→emit）
3. main.rs invoke_handler 注册表追加（main.rs:189-237）
4. **命令实现里禁止阻塞事件循环**——重操作 spawn 或 spawn_blocking（[06](06-踩坑复盘-假死.md) 铁律）

### 新增前端页面/目录
同步更新 `tools/check.mjs` 的 PAGES 数组，否则完整性校验覆盖不到。

### 新增全局快捷键动作
shortcut.rs 注册逻辑 → commands.rs 录制命令 → 前端 bindShortcutRecorder 复用录制器；录制期间记得置 SHORTCUT_RECORDING 门禁。

### 动窗口显隐/材质/WebView 前
依次通读 [06 全章](06-踩坑复盘-假死.md) 与 [07 §1/§3](07-踩坑复盘-高频回归.md)，自查三问（06 §7）。

### 发版
照抄 [08 §5](08-工程化与工具链.md) 清单执行，勿跳步。

## 3. 代码修改检查单（提交前自问）

- [ ] popup 显隐流程的三个 place_below_taskbar 调用点未被删减；suspend/resume 配对完整（close 后 suspend、open/wake 前 resume）
- [ ] Mutex 访问走 lock_unpoisoned；新增跨线程 UI 操作经 AppHandle clone 进子线程
- [ ] 新增 JS 文件带四要素头注释；跨页调用的函数已挂 window 并在"提供"清单声明
- [ ] commit 标题 `<type>(<scope>): 中文一句话`；body 写清为什么+怎么改+影响边界（它是 Release Notes 的信息源）
- [ ] 版本号未单独漂移（五处一致性由闸门兜底）

## 4. 已否决路线与暂缓事项（含重启条件）

### 已否决：方案乙 ESM 迁移
经典脚本 + check.mjs 审计的体系运转良好。触发重新评估的条件（AGENTS.md）：
- 前端规模翻倍，或多人协作出现合并冲突常态化，或 config 共享实际出 bug
- 届时可先考虑「config 抽为经典脚本单例」的廉价中间路线，而非一步到位 ESM

### 已否决：统一 invoke 双轨
popup 防御式获取与 settings 全局绑定各有生命周期依据，详见 [04 §3](04-前端架构.md)。勿再提议统一。

### 暂缓：材质系统收敛（删除 settings-general 回调手动三件套）
原则："下次因其他原因动材质代码时顺手做并实测闪烁"。单独为此开改动不值得冒回归风险（材质是本项目回归最多的问题域，[07 §1](07-踩坑复盘-高频回归.md)）。

### 暂缓：2.4G 设备电量（进行中）
feat/24g-battery 分支已有 Razer Orochi V2 实现；合入后 README「暂不支持电量」表述需同步更新，并补全各厂商驱动扩展指南（嗅探方案参考 README 外链项目）。

## 5. 快速排障索引

| 症状 | 第一排查点 |
|------|-----------|
| 启动即失败/闪退 | debug.log 是否有 `[panic]`；无则查 Builder 构建错误 MessageBox；确认 WebView2 Runtime 存在 |
| 托盘点击无反应 | debug.log 看 `[tray] click → spawn` 是否出现：出现则查 toggle 之后链路；未出现则是事件循环卡死 → [06](06-踩坑复盘-假死.md) |
| 弹窗位置错/半截弹出 | 托盘坐标双臂匹配（[07 §2](07-踩坑复盘-高频回归.md)）；toggle 心跳坐标快照日志 |
| 材质不生效 | 是否 release 构建？是否新窗口漏了恒透明出生？（[07 §1](07-踩坑复盘-高频回归.md) 四条守则逐条对） |
| 音量滑块与设备实际不一致 | volume-changed 推送链是否活着；是否踩中固件回写型设备（[07 §8](07-踩坑复盘-高频回归.md)）；静音上拖保序锚点是否被移除 |
| 应用级设备切换无效 | deviceId 是否打包接口路径；HRESULT 分类是否被吞（[07 §6](07-踩坑复盘-高频回归.md)） |
| 提交被钩子拦 | 按五类校验逐条对照 [08 §2](08-工程化与工具链.md)；误报优先扩展 check.mjs 提取规则而非 --no-verify |
